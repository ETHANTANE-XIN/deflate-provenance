Data and split

201 training and 85 test source files (6353 and 2689 streams, including 545 and 129 streams from application documents). The split is made by family: 118 real files form 72 families (same directory and a shared name prefix of at least 6 characters, or near-duplicate content), and a family never straddles the split. Independent checks on the regenerated content: test sources identical to a training source 0, near-duplicates of one 0. 131 test streams are produced identically by more than one profile and are scored against their whole label set.

Archive experiments (real ZIP writers)

72 test archives from 6 writers (7zip, dotnet, go, java, libarchive, python-zipfile); the metadata baseline was trained on 72 archives built from the training sources. Every archive is analysed exactly as dfp analyse does.

  • Genuine archives: DeflateProvenance profile correct 100%; metadata baseline profile correct 100% (same task) and exact writer correct 83% (a harder task only metadata can attempt); false alarms 0% (0% without reference encoders). the genuine archives claim 'dfp test writer (...)', which is not in the producer table, so this false-alarm rate covers the mixed-encoder and duplicate-name checks; producer checks are measured on real application files
  • Metadata rewritten to impersonate another writer: the metadata baseline followed the forgery 96%; DeflateProvenance kept its attribution 100% and disagreed with the forged writer 100%.
  • Claimed producer rewritten to a false value (with that writer's option bits): flagged 100%, by the stream evidence alone 100%; attribution kept 100%.
  • One part edited and recompressed by a different library ({'go': 48, 'zlib': 24}): archive flagged as mixed 97%; the report named the edited entry and no other 97%; when the edited entry had enough evidence to be attributed (100% of cases) it was flagged 97%. Without reference encoders (only CPython zlib's exact checks, as on a machine with nothing else installed): flagged 83%, edited entry singled out 83%.

Real application files

60 genuine files. False-alarm rate (genuine file flagged as inconsistent): 0%; inconclusive 3%. One part edited with a Python script (zlib) in 30 files: flagged 100%, localised 100%; edited with go in 60 files: flagged 100%, localised 100%. An edit is only scored where the editor's encoder differs from the file's own (30 and 0 files skipped): recompressing a zlib file with zlib reproduces what its writer would have written, which no method can detect.
